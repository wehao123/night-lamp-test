# 夜间水质资料补查结果

本次仅检查资料，没有启动厂家软件、连接硬件或编写采集应用。

## 已补查到的信息

1. `EbyteVcom/EbyteVcom/COM_Info/VSPort_ini.XML` 保存 COM11 → 192.168.2.10:4004、COM12 → 192.168.2.10:4003。它与现场说明书的示例对应不同。此为随资料保存的配置，不证明用户截图中的 COM1 当前如何映射，也不能证明哪个端口对应 HSE/HSL。
2. `data/2026-09-08.db` 中探头 `OCR / 25K00382` 有 3033 条关联原始数据的采集记录。原始体头部都是 `WHSRHSE0382`，与本次用户贴出的 HSE/0382 身份相符；不能仅凭此保证历史标定仍适用于当前硬件状态。
3. 逐条核对这 3033 条记录，全部为 596 字节数据体，按偏移 16 的 little-endian uint32 解出的积分时间与数据库毫秒值一致，按偏移 20 的 288 个 little-endian uint16 解出的数组与数据库 DN 完全一致。
4. 数据库保存的是数据体，缺少线上完整帧的校验和和尾符。因此可以用于数值解析回放，但不能据此验证现场完整帧的校验算法。单独导出一条至 `OCR0382_历史数据回放样例.json`。
5. 历史帧的第 13～15 字节并非全零，3033 条均如此。原协议所谓保留字节固定零不能作为严格拒帧条件；其实际含义待固件核实。
6. 找到 `cal/ocr/v1_0/OCR-25K00382_Cal_by_TriOS-86BD.json`，包含 288 像元波长系数和辐射定标字段。未在标定目录中找到文件名含 2100 的实际标定文件；`OCR标定文件规范.md` 的 25F02100 是示例，不是这台设备的标定证据。
7. `K值计算机制说明.md` 说明部分 OCR 固件给去暗结果加固定偏置（例如 1000），标定文件有 `dn_offset`。必须区分固件编码偏置与探测器暗场：确认采用该编码的 N 帧需撤销偏置，不能再次盲目扣暗；L/D 帧则按各自语义处理。文档定义不能替代当前固件核验。
8. 现有软件用户手册描述自动识别、手动/自动采集、曲线、SQLite 和 CSV，且称启动后打开浏览器。先前建议的 PySide6 是新开发方案，不是对已有软件 UI 技术的确认。
9. 水质 `wqa_dev_modbus.jar` 中实际存在 `wqa/adapter/MPA/MPACBDevice.class`、`modebus/pro/ModeBusClientNode.class`、多种寄存器类型组件及参数名称资源。说明有可继续分析的打包驱动，不能由类名直接确定地址、寄存器及现场型号适配。本次未反编译驱动或执行其中代码。

## 核对范围

递归核对业务资料目录；检索协议及配置；补读光谱软件操作、OCR 标定、K 值及双通道流程等相关文档；只读查询四个历史数据库；列出 ZIP、RAR、7z 内容及水质 JAR 组件。标定 ZIP 的 doc 目录共 44 个文件，与解压目录逐文件比较均一致，没有发现另一套不同版本文档。

不把“目录和关键词检索完成”表述为所有文件逐字精读：通用运行库、驱动 DLL/EXE、全部标定数值和二进制程序并未穷尽审计；没有通过运行程序验证其行为。雷达专用协议及水质正式寄存器表，在已核对的文档和归档目录中未找到。
