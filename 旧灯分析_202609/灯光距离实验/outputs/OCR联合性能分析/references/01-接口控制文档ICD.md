## 0. 网络拓扑与端口分配

```
PC(建议固定 192.168.2.100) ── R300S路由器(192.168.2.1,网关)
                                    │
                              E810-DTU(192.168.2.10)
                                    ├─ Port1 / RS485 / TCP 4001 / 9600 8N1  → 继电器(LH-IO204) + 电压电流采集(ZH-4402D, 地址02)
                                    ├─ Port2 / RS485 / TCP 4002 / 9600 8N1  → MPA-6S水质仪(地址1~32搜索) + 雷达(地址40/0x28)
                                    ├─ Port3 / RS232 / TCP 4003 / 115200    → 照度计(Ed) 【数据位/校验/停止位待验证】
                                    └─ Port4 / RS232 / TCP 4004 / 115200    → 亮度计(辐亮度探头) 【数据位/校验/停止位待验证】
```

**架构约束(必须遵守)**:
- E810 的 4 个串口 = 4 个完全独立的 TCP 端口,没有协议头复用机制。上位机对每一路必须建立独立 TCP 连接。
- E810 工作方式统一设为 **TCP Server**,上位机作为 TCP Client 主动连接。
- 心跳包、注册包、短连接、Modbus TCP↔RTU 自动转换均保持**关闭**(出厂默认关闭,现场已验证透传行为),否则字节流会被额外包裹,与本文档描述的帧格式不符。
- 同一条 RS485 总线上,任意时刻只允许一个"主站"发命令。软件必须对每个 TCP 端口(=每条物理总线)做互斥访问,不允许多个模块/线程同时向同一端口发命令。

## 1. E810-DTU(4RS1E) 串口服务器

| 项目 | 值 |
|---|---|
| Web 管理地址 | 192.168.2.10(现场静态IP);出厂恢复地址 192.168.4.101 |
| 工作方式 | TCP Server(4路独立配置) |
| 心跳包/注册包/短连接 | 关闭 |
| Modbus TCP↔RTU转换 | 关闭(保持透传) |
| TCP连接数上限 | 单端口最多6个Client(超出踢最早连接) |
| KeepAlive | 可选,TCP层标准keepalive,作为断线兜底 |
| 超时自动重启 | 默认300s无数据自动重启该端口,设<60s关闭此功能 |

**上位机侧连接策略**:
- 4条TCP连接各自独立管理生命周期,断开后由上位机主动重连(退避重试,例如 1s/2s/5s/10s 递增,上限 30s),不要依赖 E810 主动找回连接。
- 连接建立后先不发任何命令,等待 100~200ms 让链路稳定,再开始收发。

## 2. Port1:继电器(LH-IO204) — 设备上电控制

| 项目 | 值 |
|---|---|
| 协议 | Modbus RTU |
| 波特率/格式 | 9600 / N / 8 / 1 |
| 现场地址 | 0xFE(广播地址,现场单设备调试用) |
| CRC | CRC16,低字节在前、高字节在后 |

⚠️ **待办**:0xFE 是"总线上只有一台 LonHand 设备时"的调试专用广播地址。当前总线上确实只有这一台继电器,可以继续用,但**新代码里把地址做成配置项**,不要硬编码 FE——以后总线上再挂其他 LonHand 设备会冲突。

| 功能 | 命令 | 说明 |
|---|---|---|
| CH1 开(采集模块上电) | `FE 05 00 00 FF 00 98 35` | 原样回显表示成功 |
| CH1 关 | `FE 05 00 00 00 00 D9 C5` | |
| CH2 开(其余设备上电) | `FE 05 00 01 FF 00 C9 F5` | |
| CH2 关 | `FE 05 00 01 00 00 88 05` | |
| 查询两路输出状态 | `FE 01 00 00 00 02 A9 C4` | 返回 `FE 01 01 <状态字节> <CRC>`,bit0=CH1,bit1=CH2 |
| 全开(0F功能码) | `FE 0F 00 00 00 02 01 FF D1 D3` | |
| 全关(0F功能码) | `FE 0F 00 00 00 02 01 00 91 93` | |

### 2.2 供电分配

- **CH1**:仅控制 ZH-4402D 电压电流采集模块
- **CH2**:控制其余现场设备(水质仪、雷达、亮度计、照度计、搜索灯、相机等)

- 触点容量 10A/30VDC,CH2 同时带多设备时需校核总电流(含启动浪涌余量),不得超过 24V 主电源(6A)能力

### 2.3 输出端子

| 端子号 | 定义 |
|---|---|
| 9/10/11 | CH2 的 NO/COM/NC |
| 12/13/14 | CH1 的 NO/COM/NC |

## 3. Port1:电压电流采集模块(ZH-4402D)

| 项目 | 值 |
|---|---|
| 协议 | Modbus RTU |
| 波特率/格式 | 9600 / N / 8 / 1 |
| 现场地址 | 0x02(出厂默认01,现场已改为02) |
| A/B端子 | 端子5=A+,端子6=B- |
| 更新周期 | 默认100ms(寄存器004FH可调20~400ms) |

### 3.1 寄存器地址表(16位寄存器,大端;CRC小端)

| 地址 | 内容 | 类型 | 换算公式 |
|---|---|---|---|
| 0000H | 通道1瞬时值 | uint16 | 实际值 = DATA × 量程 / 10000 |
| 0001H | 通道2瞬时值 | uint16 | 同上 |
| 0002H | 通道1最大值记录 | uint16 | 同上,读取后自动清零 |
| 0003H | 通道2最大值记录 | uint16 | 同上 |
| 0004H | 功率 | uint16 | W = DATA/10000 × (电压量程×电流量程) |
| 0005H-0006H | 通道1高精度值 | uint32 | 实际值 = DATA × 量程 / 100000 |
| 0007H-0008H | 通道2高精度值 | uint32 | 同上 |
| 0009H-000AH | 通道1有符号值 | int32(补码) | 同上 |
| 000BH-000CH | 通道2有符号值 | int32 | 同上 |
| 000DH-000EH | 通道1 AD原始值 | uint32 | 24位AD原始码 |
| 000FH-0010H | 通道2 AD原始值 | uint32 | 24位AD原始码 |
| 0011H | 通道1有符号16位 | int16 | 实际值 = DATA × 量程 / 10000 |
| 0012H | 通道2有符号16位 | int16 | 同上 |
| 3000H-3001H | 通道1浮点值 | float32(IEEE754,高字节在前) | 直接为物理值,需配合0053H量程寄存器 |
| 3002H-3003H | 通道2浮点值 | float32 | 同上 |

配置寄存器(读写):004EH 零点屏蔽、004FH 更新周期、0050H 地址、0051H 波特率、0052H 校验、0053H/0054H 量程系数、0060H 网口协议模式。

### 3.2 报文示例

- 读0~8共9个寄存器:发 `02 03 00 00 00 09 85 FF`(注:地址02对应CRC需重算,现场记录值为此)
- 返回:`02 03 12 <18字节数据> <CRC>`

**量程已确认(2026-09-20)**:铭牌 ZH-4402D-14D3 = 30V*5A,量程寄存器 0053H/0054H 读到 30/5,一致。通道1=电压、通道2=电流。

实测寄存器 0..8 = `[7908, 4442, 7909, 4608, 3512, 3, 40650, 3, 25522]`(24V电源、搜索灯亮):
16位值 → 23.724 V、2.221 A;功率寄存器 → 52.68 W ≈ V×I,自洽。
**手册里 32 位"高精度值"(0005H~0008H)的公式 DATA×量程/100000 与实测对不上**(算出 71.2 V / 11.1 A,实际约为 16 位值的 30 倍 / 50 倍),原因未查明,驱动已不输出这两项(16位分辨率已达 3mV / 0.5mA)。

现场铭牌/联调记录写的型号是 **MIK-WSR201**,但拿到的官方说明书标的是 **U-102RSW-CN2**("美仪"2.0协议,协议版本寄存器0x2000应为0x0200)。说明书里的寄存器地址跟现场已验证的两条命令(`20 01`/`20 02`)完全对得上,可以确认这本说明书就是实物的真实协议,不管外壳贴的是什么牌子。

| 项目 | 值 |

### 4.2 故障码(0x2200寄存器按位解读,仅列与测距可信度直接相关的位)

| Bit | 含义 |
|---|---|
| 5 | 没有标定完成 |
| 8 | 距离未校准 |
| 10 | 电流未校准 |
| 13 | 雷达板通信异常 |
| 14 | 雷达板测量异常 |

其余位是存储类异常(配置/标定/曲线存储异常等)或预留位,暂不特别处理。

### 4.3 命令示例(现场已验证)

| 功能 | 命令 | 预期返回 |
|---|---|---|
| 读设备类型 | `28 03 20 01 00 01 D9 F3` | 应含 `0B 01` |
| 读距离 | `28 03 20 02 00 02 69 F2` | `28 03 04` + 4字节float(单位m) + CRC |
| 读故障码 | `28 03 22 00 00 02 <CRC>` | `28 03 04` + 4字节故障码 + CRC(CRC需现算,代码里用`build_read_holding_registers`自动生成) |

**开机自检建议**:发"读设备类型"命令校验返回是否含 `0B 01`;通过后再读一次故障码(0x2200),非零则记录报警(不阻断运行,原理同其它设备的降级策略)。

**字序已实测确认(2026-09-20):32位数(float、long)都是低位字在前(CDAB)**,说明书没写。依据:距离寄存器 `f82d 3fb4` 按 ABCD 得 -1.4e34 m、按 CDAB 得 1.41382 m;量程/安装高度寄存器 `0000 4170` 按 CDAB 恰好是 15.0 m(出厂量程),液位值 `50ba 4159` ≈ 13.58 m ≈ 15 − 距离。故障码 0x2200 的字序是类推的(目前值为0)。

当日读到的状态:协议版本 0x0200、故障码 0、测量模式 0x2504=1(距离模式)、滤波系数 0、量程=安装高度=15.0 m。**距离 1.414 m 尚未用卷尺核对**。

## 6. Port3/4:光谱探头(照度计 Ed / 亮度计)

### 6.0 现场实测确认(2026-09-20)——以本小节为准,下面 6.1~6.5 是实测前的推断,与本节冲突处以本节为准

已确认是 **OCR 协议**(安华海洋固件 OCR V2.3c),通信参数 115200 8N1(E810 端口3/4网页设置:115200/None/1,TCP Server,最大连接数1、超出KICK)。

| 端口 | 探头 | SN | DEV_TYPE | 积分时间(自动) |
|---|---|---|---|---|
| 4003 | 照度计 | 0382 | HSE(辐照度) | 8000 µs |
| 4004 | 亮度计 | 2100 | HSL(辐亮度) | 64000 µs |

- **命令必须以 `\r\n` 结尾**;不带换行会得到 `[ERROR]unknown command`
- `C\r\n` → `[INFO]SN / DEV_TYPE / BAUDRATE` 三行设备信息
- `CAL\r\n` → 波长多项式 A0,B1..B5(`CAL_SINDEX: 1`);按 λ=ΣLi·n^i 计算,n=像元编号(第一个像元编号=CAL_SINDEX),照度计 315.0~885.5nm。**2026-09-21 已核对**:与厂家上位机库里 TriOS 标定文件 OCR-25K00382 的 288 个波长完全一致(误差0nm)。旧公式(n−1)整体偏一个像元约2.7nm,已修正。CAL_SINDEX≠1 的情况未验证
- `CAL_K\r\n` → 全是 `NAN`:这两支探头**设备内没有K值**,所以 `SBP`/`SAP`(物理量)返回 `[ERROR]SBP: 12`,**只能取DN**,物理量需在上位机用标定文件换算(标定上位机V3 的 `cal/ocr/` 下按SN查找)
- `SBN\r\n`(去暗DN,含约1000的dn_offset)/`SBL\r\n`(亮场,未去暗)→ 599字节二进制帧,取一帧约0.2~0.7s:
  `"WHSR"(4)+设备类型(3)+SN(4)+光类型(1:L/D/N)+帧号(1,ASCII数字)+保留(3)+积分时间us(int32小端)+288×uint16小端+校验(1)+"\r\n"`
- 校验 = 校验字节之前所有字节之和取低8位(4帧实测全部吻合);**DN是无符号uint16**(有值>32767)
- 现场曾出现探头完全无响应(此前疑与发送了不规范命令有关,原因未确认),给继电器 CH2 断电再上电后恢复;探头上电后先输出 `Version: IES_MDB_Bootloader_V1.0.0...` 与 `[INFO]OCR:V2.3c...` 两段开机banner,约2.5s后可接受命令
- 未验证:`SAN`/ASCII 帧、手动指定积分时间(`SBN <us>`)、`AUTO` 模式(**禁用**)

原始实测帧已存入 `采集软件/tests/fixtures/`,作为回归测试数据。

⚠️ 以下 6.1~6.5 为实测前的推断,保留作历史记录:联调说明书仅确认波特率115200,数据位/校验/停止位未记录。根据立项报告BOM,两支探头均为安华海洋 **C12880MA模组辐亮度计**,据此推断最可能是 **OCR协议**。

### 6.1 验证步骤(开工第一步必做)

**优先方法:抓包厂家上位机的真实通信(比手动猜命令可靠,优先用这个)**

现场这两支探头(C12880MA模组/OCR-18E00196)是安华海洋"标定上位机V3"/IES-SpecCheck 这套软件的目标设备,该软件大概率能直接识别、采集。具体做法:

1. 用"亿佰特VCOM"把 `192.168.2.10:4003`(照度计)/`4004`(亮度计)各映射成一个虚拟串口(参照联调文档里 MPA-6S 用 COM10 的同款做法)
2. 打开"标定上位机V3",连接对应虚拟串口,尝试识别设备、采集一次数据
3. 同时用 Wireshark 抓 `tcp.port==4003`(或4004)的包——这条TCP连接就是串口字节流的透明搬运,抓到的就是真实设备协议的原始报文,比对文档里的协议假设更可靠
4. 把抓到的握手/采集报文整理出来,更新本节6.2/6.5的协议假设为"已确认"

**备用方法:手动试探(仅当厂家软件连不上/无授权时使用)**

1. 网络调试助手 TCP Client 连接 192.168.2.10:4003(照度计)/ 4004(亮度计)
2. 发送 ASCII 文本 `C`(不需要额外结束符),观察是否返回 `[INFO]/[DEBUG]` 格式的多行文本(型号、波特率、积分档位等)
3. 如果没反应,尝试 IEP 协议握手:发送 `T\r`,观察是否返回 JSON(`DeviceType/SpectrometerType/SN/...`)
4. 确认协议族后,再验证数据位(8N1是常见默认,但需实测确认)

### 6.2 OCR协议命令集(最可能的协议,88%把握基于型号命名推断)

| 命令 | 作用 |
|---|---|
| `C` | 握手/查询配置,回复多行INFO/DEBUG文本 |
| `BAH` / `B<文本≤256字节>` | 通信自检,原样回显 |
| `CAL` | 查询波长标定系数(A0,B1~B5六阶多项式) |
| `CAL_K` / `CAL B` | 查询设备内置K值/B值数组(标定系数固化在设备Flash,无需外部标定文件) |
| `SAP` | 采集物理量,ASCII逗号分隔 |
| `SBP` | 采集物理量,二进制float(288点) |
| `SA{L\|D\|N}[ <积分时间us>]` | 采集亮值/暗值/去暗码值,ASCII帧,可选手动积分时间 |
| `SB{L\|D\|N}[ <积分时间us>]` | 同上,二进制帧 |
| `SET BAUDRATE <值>` | 1200~921600,需被1200整除 |
| `SET DARK_COUNT <0/1>` | |
| `SET LIGHT_COUNT <1~20>` | |
| `INTTIME <0~99自动 / 100~2048000强制>` | 自动模式下调节积分时间 |

**禁止发送 `AUTO` 进入设备自动模式** —— 会屏蔽绝大多数上位机命令,只能被动等待。软件应始终工作在命令模式主动轮询。

### 6.3 二进制物理量帧结构(SBP)

```c
struct {
    char head[4];         // 固定 "WHSR"
    char device_type[3];  // "HSE"=辐照度探头(照度计) / "HSL"=辐亮度探头(亮度计)
    char sn[4];
    uint8_t frame_num;
    uint8_t reserved[4];  // 固定0x00
    float spec_phy[288];  // 288点物理量
} // 之后追加 1字节校验(字节和取低8位) + "\r\n"
```
Python 解包串:`'<4s3s4sb4b288f'`(物理量)/ `'<4s3s4s1sb3bi288h'`(DN值帧,多了 light/dark/none 标识和积分时间字段)

校验算法:`checksum = sum(data) & 0xFF`(简单字节和,不是CRC)

### 6.4 物理量换算公式

```
P_λ = (DN_λ - dn_offset) × K_λ / T_int
```
- `dn_offset`:典型值1000(固件为避免uint16下溢加的偏置,换算前需减去)
- `T_int`:积分时间(ms)
- `K_λ`:每像元灵敏度系数,OCR探头该系数直接从设备读(`CAL_K`/`CAL B`),无需外部标定文件

### 6.5 备选协议:IEP/IEU(若实测不是OCR协议)

| 命令 | 作用 |
|---|---|
| `T\r` | 查询设备信息,返回JSON,上电也会主动推送一次 |
| `A1~A5\r` | 设波特率9600/19200/38400/57600/115200 |
| `I<n>\r` | 设积分档位(合法值:5/8/16/32/64/128/256/512/1024/2048/4096/8192) |
| `S\r` | 标准采集(自动扣暗) |
| `M\r` | 混合采集 |
| `L\r` / `D\r` | 亮场(不扣暗)/暗场(不扣暗) |
| `R\r`(仅IEU) | 自动积分去暗,超时建议≥60秒 |
| `G\r` | 取数,返回定长二进制包(520字节单帧 / 1544字节混合模式) |

帧结构(单帧,520字节):`包头5字节('A''H'+模式+积分档位+帧号)` + `256点uint16大端` + `CRC8(1字节)` + `\r\n`。CRC8参数:初值0x00,多项式0x07(递归实现,非查表)。

TriOS RAMSES协议(二进制8字节定长指令帧,含转义机制)作为更底层备选,细节见 `标定上位机V3/doc/sensor/TriOSRamses协议.md`,本项目探头型号推断优先级较低,仅在OCR/IEP均验证失败时考虑。
